# Как использовался ИИ

**Инструмент:** Claude Code (модель Claude Opus 5.5), 24 ноября 2026.

**Скиллы:**

- `frontend-design` (Anthropic) — план дизайна и прототип;
- `shadcn` (shadcn/ui) — выбор и настройка компонентов;
- `web-design-guidelines` (Vercel) — финальное ревью.

Скиллы `shadcn` и `web-design-guidelines` установлены через `npx skills add` и лежат в `.agents/skills`, версии зафиксированы в `skills-lock.json`.

Скилл `unslop` официального источника не имеет: `npx skills find unslop` нашёл только несколько малоизвестных форков. Их не ставили. Тексты интерфейса и README вычитаны вручную по тем же правилам: коротко, активный залог, конкретные ошибки с подсказкой, что делать.

## Промпты

### 1. Основной бриф (на всю работу)

> Lab 8 — GitHub Issues Report Viewer. Implement the project in this repository… initialize it with Next.js App Router, TypeScript, and shadcn/ui… A user selects a Monday, submits the form, and sees two tables, one grouped by issue type and one grouped by author… Create an AI-assisted prototype first… Require a valid date that falls on a Monday. Show loading feedback and prevent repeat submissions… Create a separate, importable n8n workflow named «Read weekly report»… Use Playwright to mock /api/report and verify…

Полный текст брифа лежит у автора. К брифу приложен экспорт workflow Lab 7.2 — по нему ИИ взял схему таблицы `lab72_weekly_stats` (`repository`, `week_start`, `stats_json`) и формат `stats_json` (`totals`, `byType.{bug,task,feature,other}`, `byAuthor[]`).

### 2. Прототип

ИИ работал по скиллу `frontend-design`: «сначала план — цвет, шрифт, раскладка, принципы; проверь план на шаблонность; потом код». План и решения записаны в [`prototype/README.md`](../prototype/README.md). Прототип показывает все шесть состояний, которые требует бриф.

### 3. Интерфейс

На основе прототипа и правил скилла `shadcn` (формы через `Field` + `FieldLabel`, пустое состояние через `Empty`, ошибки через `Alert`, загрузка через `Skeleton` и `Spinner`, только семантические цвета темы) ИИ сделал:

- форму с валидацией и защитой от повторной отправки;
- серверный маршрут `/api/report`, который проверяет ответ n8n;
- workflow `Read weekly report`.

### 4. Тесты

> Use Playwright to mock /api/report and verify: keyboard input and validation for an empty date and a date that is not a Monday; a visible loading state and exactly one request when the user submits again while a response is pending; an empty response, a server error, and a successful retry; the full flow from picking a date to seeing both populated tables.

ИИ добавил тесты сверх брифа:

- неполная дата;
- обрыв сети;
- неверный формат ответа;
- отчёт с нулями;
- ссылка `?week=`;
- контракт маршрута с заглушкой n8n;
- e2e на мобильном экране.

## Второй раунд: шире функциональность, лучше UX

### Промпт

> bro i think its pretty dumb that you have to choose a monday particularly, maybe you should be able to just select a date or like view last N issues, just broaden the functionality of the site and make it more useful and overall please try to improve UX, because ive also seen some bugs and glitches in the UI

ИИ задал три уточняющих вопроса. Ответы автора:

- **Выбор даты:** любой день → его неделя.
- **«Последние N»:** тренд по последним неделям из сохранённых отчётов, а не список задач из GitHub API.
- **Замеченный баг:** в окне ошибки «одно предложение без точки, а следующее начинается с заглавной».

### Что сделано

- **Любой день → его неделя.** Подсказка под полем называет неделю. Клик открывает календарь, будущие даты недоступны. Будущая дата — отдельная ошибка проверки.
- **Переходы.** Быстрый выбор «Прошлая неделя» и «Позапрошлая неделя», стрелки «Предыдущая» и «Следующая». В будущее листать нельзя.
- **Текущая неделя.** Отдельное пустое состояние «Неделя ещё идёт»: когда появится отчёт, плюс кнопка «Открыть прошлую неделю».
- **«Последние недели».**
  - 4, 8 или 12 недель через shadcn `ToggleGroup`.
  - Таблица с полосками «Создано» и «Закрыто», недели без отчёта отмечены. Клик по неделе открывает её отчёт.
  - Данные идут через новый маршрут `/api/history` и новую ветку workflow `GET /webhook/lab8-weekly-history`. Её ИИ добавил в живой n8n через API, предварительно сохранив резервную копию workflow.
- **Ссылка `?week=`** принимает любой день.
- **Ровнее загрузка.** Кнопка фиксированной ширины. При переходе между неделями прежний отчёт остаётся приглушённым вместо скелетона.

## Третий раунд: фоны страницы

### Промпт

> i want to be able to choose themes: 1) plain color just the way it is now 2) https://www.ascii-magic.com/ascii/desert-buttes-road this as a background ofc u have to make sure everything is readable etc 3) https://www.ascii-magic.com/ascii/fuji-dawn-lake 4) https://www.ascii-magic.com/ascii/harbour-neon-skyline — please use lines style for those backgrounds

### Что сделано и почему так

- **Лицензия.** ИИ сначала проверил, откуда сцены и можно ли их брать. Это открытый пакет `ascii-magic-art` под MIT. Исключение — две сцены по фотографиям, и они сюда не входят. Уведомление об авторах лежит в `THIRD_PARTY_NOTICES.md` и в подписи под панелью.
- **Без внешних скриптов.** Вместо скрипта с чужого CDN подключён npm-пакет с зафиксированной версией 1.1.0. Перед установкой ИИ скачал архив пакета и проверил три сцены и плеер: нет сетевых запросов и `eval`. Сцены грузятся отдельными чанками только при выборе фона.
- **Стиль «lines»** — опция плеера `look: "lines"`. Сцена растягивается на весь экран как `cover`.
- **Читаемость.** Всё содержимое на светлой панели с непрозрачностью 96%, приглушённый текст остаётся контрастнее 4.5:1 над самой тёмной сценой. Тест проверяет непрозрачность панели для каждого фона.
- **Движение.** Анимация ставится на паузу вне экрана. При `prefers-reduced-motion` кадр стоит — на это есть тест, как и на то, что без этой настройки кадры меняются.
- **Без мигания.** Выбор сохраняется, а скрипт в `<head>` ставит его до первой отрисовки.

## Четвёртый раунд: свои цвета у тем, плавные переходы, меню

> look, now the window is the same color for all of the themes you should fix it, and the transition between plain color and wallpaper is too shifty, fix it also. make all the transitions between themes smoother. also can you please rework that theme choosing, i want it to be a list of themes that pops out when i click on it and then i can choose from the list

### Что сделано

- **Свои цвета.** У каждой темы своя палитра токенов: песочная «Пустыня», сиреневая «Фудзи», тёмная «Гавань». Перед вёрсткой ИИ посчитал контраст всех пар «текст/фон», включая цвет панели поверх сцены, — все не ниже 4.5:1. Цвета метрик для тёмной панели проверены скриптом `validate_palette` (первые варианты не прошли проверку по светлоте, взяты тёмные шаги из эталонной палитры).
- **Без сдвигов.** Раньше тема с фоном добавляла отступ сверху в 24vh и поля панели — содержимое прыгало. Теперь раскладка одна для всех тем; у «Без фона» панель просто цвета страницы.
- **Плавность.** Цвета перетекают за 0.4 с через временный класс на `<html>`, сцены сменяются наплывом. При `prefers-reduced-motion` переходов нет.
- **Меню.** Вместо ряда кнопок — `DropdownMenu` с радиопунктами, картинкой и описанием каждой темы.

## Пятый раунд: тормоза

### Промпт

> still a bit laggy but i think it will work → yeah, make those changes and push

ИИ предложил три причины и способа и сделал два согласованных.

### Что сделано

1. **Убрано размытие (`backdrop-filter`) под панелью.** Браузер пересчитывал его на каждом кадре анимации.
2. **Сцена рисуется в 1× даже на Retina.** Плеер пакета всегда рисует в 2× и не даёт это изменить, поэтому сцену теперь рисует свой короткий цикл на экспортируемых функциях пакета: `withLook` переводит кадр в стиль «lines», `paint` рисует его через атлас глифов. Шаги те же, что у плеера, но с нашим разрешением.
3. **Панель стала непрозрачной.** Без размытия сквозь панель на 96% были видны движущиеся линии за текстом. Контраст от этого только вырос.

### Замер

Скрипт Playwright: окно 1440×900, `deviceScaleFactor: 2`, тема «Гавань» с анимацией, 5 секунд, среднее по трём прогонам. Занятость главного потока считалась по метрике `TaskDuration` из протокола DevTools, длинные кадры — через `PerformanceObserver` с типом `long-animation-frame`.

| | до | после |
|---|---|---|
| Размер канваса | 3200×1800 | 1600×901 |
| Главный поток занят | 672 мс/с | 482–488 мс/с |
| Кадров в секунду (requestAnimationFrame) | 45 | 59–60 |
| 95-й перцентиль длительности кадра | 33.4 мс | 16.8–22.3 мс |
| Длинных кадров (> 50 мс) за 5 с | 26.7 | 0 |

Оставшаяся нагрузка — сама генерация кадра сцены (около 20 000 клеток, 15 раз в секунду). Если понадобится ещё легче, следующий шаг — снизить частоту кадров до 10 в секунду.
